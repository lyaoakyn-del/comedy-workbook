# System Overview

## The Core Idea

Material doesn't appear fully formed. It moves through stages — from a vague observation to a tested joke to a reliable bit in your set. This system makes that movement visible and intentional.

```
Observation → Raw idea → Draft joke → Tested joke → Set piece
   (2-ideas)              (3-in-dev)    (4-ready)    (5-setlists)
```

The bottleneck is almost never coming up with ideas. It's developing them. This system forces development by making it frictionless.

---

## The Five Stages

### Stage 1: Exercises (`1-exercises/`)
Structured exercises from comedy books and methods. Not for material development — for building the habit of noticing. Do these when starting out or when feeling creatively stuck.

### Stage 2: Ideas (`2-ideas/`)
Everything goes here first. Morning notes, voice memo transcriptions, random observations. No filtering. No judgment.

**Rule:** Write it down before you decide if it's funny.

Two sources:
- **Morning notes** — written, stream-of-consciousness, ideally before checking your phone
- **Audio notes** — voice memos transcribed into text

### Stage 3: In Development (`3-in-development/`)
Observations that showed promise get their own file here. This is where the actual writing happens.

One observation = one file. Use the `joke-development.md` template.

**Rule for moving from Stage 2 to Stage 3:** You can imagine a punchline. That's the only threshold.

**Rule for moving from Stage 3 to Stage 4:** The bit got a genuine laugh at least 3 times on stage.

### Stage 4: Ready (`4-ready/`)
Tested material. These bits work. They're the building blocks of your sets.

Don't over-populate this folder. If something is here, it should be something you'd actually perform.

### Stage 5: Set Lists (`5-setlists/`)
Assembled sets from Stage 4 material. Use the `set-list.md` template.

File naming: `YYYY-MM-DD_venue-name.md`

### Stage 6: Performance Analysis (`6-performance-analysis/`)
Post-show notes. Fill in immediately after performing — not the next morning. Use the `performance-analysis.md` template.

---

## The Weekly Rhythm

**Daily (15-20 min):**
- Morning note
- Transcribe any voice memos from the day

**2-3x per week (30-45 min):**
- Pick 1-2 observations from Stage 2
- Write a joke development file for each

**After every show:**
- Fill in performance analysis
- Update joke files with reactions
- Move material to 4-ready if it's earned it

**Monthly:**
- Review Stage 3 — what's stalled? Shelve or push
- Review Stage 4 — anything no longer performing? Archive it

## The Tag System

Tags go at the bottom of every file.

| Tag | Stage | Meaning |
|-----|-------|---------|
| `#черновик` | 2 | Raw, unworked |
| `#вработе` | 3 | Actively developing |
| `#проверено` | 4 | Stage tested, works |
| `#отложено` | any | Shelved, not deleted |
| `#колбэк` | any | Links to another bit |

---

## File Naming

Consistency matters when you have 200+ files.

```
YYYY-MM-DD_description.md
```

Examples:
```
2026-01-15_morning.md
2026-01-15_topic-observation.md
2026-01-20_open-mic-downtown.md
```
